# 隐私与安全设计

## 1. 威胁模型

| 威胁 | 本地优先对策 |
|---|---|
| 服务器被攻破 / 内部泄露 | 无服务器，数据不出设备 |
| 数据贩卖 | 产品原则禁止；代码中无任何数据上传路径 |
| 传输窃听 | 无网络传输（MVP） |
| 手机丢失 / 被盗 | 系统级加密 + App 锁（生物识别，P1） |
| 本地数据库被读取 | SQLite 默认加密为 Phase 2（SQLCipher） |
| 恶意软件读取文件 | 文件存于 App 私有目录；iOS/Android 沙箱隔离 |

## 2. 数据最小化

- 只采集保单对比所需字段，不采集无关个人信息。
- 健康险字段按 sensitive information 对待。
- 未来任何云能力上线前，必须单独评审并取得用户明确同意。

## 3. AI 处理规则

- MVP 默认**不上传任何文档**。
- 云端 AI（若启用）：单份文档、显式授权、传输加密、处理完即删、不用于训练、可审计。
- 提取结果以 JSON 存于本地 `documents.extracted_json`，保留来源文件路径。

## 4. 上架声明

- App Store / Google Play 隐私标签：MVP 如实填写"不收集数据"。
- 仍需提供隐私政策链接（仓库 `docs/PRIVACY.md` 可作为底稿）。

## 5. 合规

- 澳洲《隐私法》APPs：本地优先显著降低义务，但健康信息仍需按敏感信息管理。
- 上线推荐/导流前：咨询保险合规律师（AFSL / general advice / referral）。
- 政策承诺：**不卖数据、不默示共享、透明披露**。
